# Blueprint research: AE2 26.1

These research notes include candidates and design caveats. The planner now offers adjustable controller, provider/assembler, CPU, charger, processor and furnace designs plus the Simple Certus Farm. The processor layout and automatic patterns have been tested by the user; the furnace build still needs an end-to-end in-game crafting test; the other unlisted candidates remain unimplemented. The order balances usefulness with validation work; it is not a promise of compatibility with every modpack configuration.

1. **Controller modules.** Offer a single ME Controller, then a small, valid ring or expansion for an existing controller. A grid cannot contain separate controllers: every controller block on it must form one connected multiblock. The complete shape must fit within 7×7×7, and a block may have neighbours on both sides along at most one axis. Validate the proposed result together with the existing network before placement, and avoid accidentally joining two controller networks. A controller requires power, and each face normally supplies up to 32 channels; cables, channel settings and routing can create bottlenecks. [Controller rules](https://guide.appliedenergistics.org/26.1/items-blocks-machines/controller/) · [Channels and channel modes](https://guide.appliedenergistics.org/26.1/ae2-mechanics/channels/)
2. **Pattern provider and assembler modules; crafting CPUs.** Start with one provider and one molecular assembler, then offer larger tiles. Clearly distinguish the provider/assembler from the crafting CPU and encoded patterns required for actual autocrafting. CPU options can start with a single crafting storage block and grow to a solid rectangular prism including storage and optional coprocessors. Avoid unintended connections to adjacent CPUs, which could merge them. [Autocrafting](https://guide.appliedenergistics.org/26.1/ae2-mechanics/autocrafting/) · [Crafting CPU construction](https://guide.appliedenergistics.org/26.1/items-blocks-machines/crafting_cpu_multiblock/)
3. **Charger automation.** The guide's on-demand design uses a pattern provider, charger and return subnet. It still needs a correctly encoded processing pattern and a powered, connected main network with an available crafting CPU. A continuously stocked charger is a different configuration and should be identified separately. [Charger automation](https://guide.appliedenergistics.org/26.1/example-setups/charger-automation/)
4. **Processor automation.** The guide's AE2-only design uses five inscribers and several isolated pipe subnets. Place the correct press in each inscriber, use the correct sided connections and configure the filters and processing patterns; the press should not be consumed as a recipe ingredient. Provide smaller or standalone alternatives only after validating their item flow. [Processor automation](https://guide.appliedenergistics.org/26.1/example-setups/processor-automation/)
5. **Furnace or machine automation.** The furnace has separate top input, side fuel input and bottom output. An initial simple version can use separate buses; the guide's one-channel version uses a subnet and a directional provider. A general third-party machine cannot be assumed to have furnace-style sides or capabilities. [Furnace automation](https://guide.appliedenergistics.org/26.1/example-setups/furnace-automation/)
6. **Fluix production and specialized storage.** The throw-in-water setup can make fluix using charged certus; it requires a correctly configured formation/annihilation arrangement and pattern. A storage subnet can isolate farm output, but needs user-selected item filters, cells and priorities. Treat water, recipes and existing-world clearance explicitly. [Throwing-in-water automation](https://guide.appliedenergistics.org/26.1/example-setups/throw-in-water-automation/) · [Specialized local storage](https://guide.appliedenergistics.org/26.1/example-setups/specialized-local-storage/)

Later candidates include level-emitter stock control, cobblestone generation, P2P networks, quantum bridges, spatial storage and more advanced Certus farms. They require additional user choices, world anchors or paired endpoints; a preview alone does not guarantee a functional setup. The [26.1 example index](https://guide.appliedenergistics.org/26.1/example-setups/example-setups-index/) is a useful catalogue.

The installed AE2 26.1.13-beta jar includes its guide's example SNBT assemblies, such as `assembler_tower.snbt`, `crafting_cpus.snbt`, `charger_automation.snbt`, `processor_automation.snbt`, `furnace_automation.snbt` and `controllers.snbt`, under `assets/ae2/ae2guide/assets/assemblies/`. They are useful references for layouts and previews. They may contain demonstration-only blocks, inventories, patterns or configuration: derive and verify each build's material list and settings instead of placing a guide scene unchanged.

Use the 26.1 guide rather than older AE2 tutorials when evaluating mechanics. In this version, certus grows from budding blocks; flawless budding blocks do not degrade but normally cannot be harvested with a pickaxe. [Certus growth](https://guide.appliedenergistics.org/26.1/ae2-mechanics/certus-growth/)
